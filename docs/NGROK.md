# Связь с Mac через ngrok

Один HTTPS-адрес передаёт HTTP и WebSocket `/v4/listen` в локальный backend.
Аудио проходит через ngrok и сохраняется на Mac. Готовый WAV можно отдельно
обработать [локальным Parakeet-MLX или WhisperX](LOCAL_STT.md) и получить разговор в приложении.

Проверены установка и повторная установка в изолированном окружении текущего Mac,
а не на втором чистом компьютере. Через мобильную сеть отдельно получены записи
микрофона iPhone (19,19 секунды) и CV1 (16,70 секунды): WAV PCM16 mono 16 kHz,
`decode_errors=0`, речь разборчива при прослушивании. CV1 пишет тихо.
Повторная запись микрофона iPhone после перезапуска туннеля также прошла.

## Установка и настройка

Команды выполняются из корня репозитория в локальном Terminal:

```bash
bash scripts/local-mac.sh install
bash scripts/local-mac.sh configure
bash scripts/local-mac.sh up
bash scripts/local-mac.sh status
```

После подготовки локальной модели включите
[автоматическую обработку новых записей](LOCAL_STT.md):
`bash scripts/local-mac.sh auto-transcribe-on`. При последующих `up` обработчик
запускается вместе с сервисами; модель и очередь остаются на Mac.

Установщик рассчитан на macOS с Apple Silicon. Он переиспользует зависимости,
недостающие системные пакеты устанавливает через Homebrew. Python 3.11.15 и
backend-пакеты закреплены в репозитории, Firebase CLI — в `package-lock.json`.
Flutter, Xcode, CocoaPods и модели распознавания установщик не добавляет.
Требования к отдельной сборке приложения — в [инструкции iOS](LOCAL_SETUP.md#приложение-ios).

Создайте аккаунт на [ngrok](https://dashboard.ngrok.com/signup) и получите его
HTTPS-адрес. Мастер запросит адрес и скрытый authtoken. Пустой ввод authtoken
переиспользует уже настроенный локальный агент. Секреты не нужно отправлять в чат.

Отдельный случайный **ключ приложения** мастер показывает один раз в Terminal.
Backend сохраняет только его SHA-256; ngrok authtoken хранится в приватном
конфигурационном файле агента. Это разные ключи. Повторная настройка сохраняет
прежний ключ приложения и данные.

Backend слушает `127.0.0.1:20000`; диагностический API агента — `127.0.0.1:16040`.
Firebase emulators и Redis слушают только loopback и не имеют публичных туннелей.
Агент запускается с `--inspect=false`. Доступны прежние разрешённые backend-маршруты;
для запросов, кроме `/v1/health`, нужен ключ приложения. Его проверка выполняется
до development auth fallback. Новые traffic policies ngrok не добавляются.

## Приложение и проверка

В локальном приложении откройте «Локальный Mac» перед входом либо из настроек.
Введите HTTPS-адрес и ключ приложения, затем проверьте подключение. Профиль
проверяется через `/v1/users/profile`; Firebase-вход с телефона не используется.
Ключ хранится в Keychain и отправляется только настроенному HTTPS/WSS-серверу.
Смена адреса останавливает запись; пересборка приложения для нового адреса не нужна.
Ошибка сети сохраняет настройки, отказ ключа требует повторного подключения.
Запрос к `https://<ваш-адрес>/v1/health` должен вернуть `200 {"status":"ok"}`.
Он проверяет доступность сервера; ключ проверяется кнопкой в приложении.
Для проверки реального аудиопути запустите команды и введите ключ приложения
в скрытом поле Terminal:

```bash
bash scripts/local-mac.sh audio-smoke
OMI_AUDIO_SOURCE=phone bash scripts/local-mac.sh audio-smoke
```

Они отправляют синтетический звук и проверяют WAV и метаданные в
`.local/dev-harness/ngrok/services/storage/listen-captures/`.
Реальные записи и `.local/` не добавляйте в Git.

Для CV1 включите устройство, дождитесь подключения и нажмите **▶ Начать запись**
на карточке CV1. После 10–30 секунд речи нажмите **■ Остановить запись**.
Мьют приостанавливает звук внутри записи. Нижний `+` (микрофон телефона) временно
неактивен; прочие [временные ограничения](TEMPORARY_DISABLED_FEATURES.md) перечислены отдельно.
В прежних сборках без этих кнопок для завершения CV1 требовалось полностью закрыть приложение.
Проверьте WAV нужного источника:
длительность, `decode_errors=0` и разборчивость речи. При переключении источников
возможны пустые или короткие дополнительные файлы. Сохранность при обрывах
и исправление жизненного цикла записи в этот релиз не входят.

## Остановка и изменения

Туннель работает в фоне, пока жив процесс агента. Остановка затрагивает только
собственные процессы и сохраняет данные, профиль и ключ:

```bash
bash scripts/local-mac.sh down
```

После остановки `bash scripts/local-mac.sh edit-connection` меняет адрес/authtoken,
сохраняя ключ приложения. `bash scripts/local-mac.sh rotate-key` заменяет ключ,
если он потерян или отозван; новый нужно ввести в приложении. Затем выполните `up`
снова. Чужой процесс на нужном порту установщик не останавливает.

## Разработка и выпуск

```bash
make test-offline
make test-transport-app
```

Нужны установленные backend-зависимости и Flutter 3.44.5. Команды проверяют
backend, harness, приложение и анализатор; CI запускает отдельные проверки
транспорта без живых сервисов. Публичный туннель проверяется отдельно.

Перед iOS-сборкой фиксируется `build/reuse/blocked` по фактическим входам; после
сборки отдельно проверяется и устанавливается точный артефакт. Финальная приёмка:
выполнить отдельные записи обоих источников по инструкции выше, затем повторить
запись после перезапуска туннеля.

Транспорт соответствует документации ngrok:
[WebSockets](https://ngrok.com/docs/using-ngrok-with/websockets),
[параметры агента](https://ngrok.com/docs/gateway/agent/cli).
